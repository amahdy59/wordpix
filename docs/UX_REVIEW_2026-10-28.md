# Mobile, navigation, theme and performance review

Review date: 28 October 2026. Release: 0.1.96.

## Scope and approach

Reviewed the shared shell and page/lesson headers, the five main destinations,
vocabulary study, and the four specialist lesson shells. The supplied phone
screenshot reproduced a flex-layout failure in `StudyShell`: action controls
consumed almost the entire row and left the unit title wrapping one letter at a
time. The review preserves the existing curriculum, unlock rules, unit identities,
progress state machines, and five-tab information architecture.

The light theme takes its direction from [the portfolio reference](https://creativemahdy.space/):
warm neutral surfaces and static tiled grain. This is a visual design choice,
not a claim of a clinical benefit or reduced eye strain.

## Changes

| Area                      | Result                                                                                                                                                                                                                                   |
| ------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Light mode                | Warm paper canvas and raised ivory surfaces replace bright white. A small inline SVG tile adds subtle grain without another request, moving overlay, or animation. Dark, high contrast, forced colors and print omit the texture.        |
| Contrast                  | Deepened light-mode status accents to retain 7:1 on both paper surfaces, including a conservative darkest-grain calculation.                                                                                                             |
| Shared page headers       | Titles and actions use separate rows until desktop width; actions wrap within their available space.                                                                                                                                     |
| Vocabulary study          | The unit title has its own row on phones. Language and activity controls share a separate row with 44 px minimum targets. The header remains outside the content scroller.                                                               |
| Activity drawer           | Named navigation, an explicit trigger-to-dialog relationship, safe-area padding, an inert background header, focus return after dismissal, and closing when returning to the overview.                                                   |
| Specialist lessons        | The larger context heading scrolls away on phones while the compact section disclosure remains available. Desktop retains its side rail. Escape closes the disclosure and returns focus. Existing locked/completed states are preserved. |
| Business                  | Removed the duplicated top header and duplicate heading ID; the remaining heading retains the localized unit number and title.                                                                                                           |
| Pronunciation             | The context title can wrap instead of truncating.                                                                                                                                                                                        |
| Short screens and filters | Curriculum sticky controls share the short-height safeguard. Expanded library filters have a bounded scroll area on mobile to avoid covering the reading area or jumping off-screen.                                                     |
| Scenario player           | Corrected untranslated play/pause labels and enabled anonymous cross-origin caption requests; existing media URLs are unchanged.                                                                                                         |

## Header and information architecture decisions

| Destination        | Header/navigation behavior                                                                                                                                                          |
| ------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Home               | Keep the greeting in normal flow; persistent shell controls and five tabs provide orientation.                                                                                      |
| Learn              | Keep the level selector sticky when there is sufficient vertical space. The vocabulary path remains the primary browser, followed by separate specialist courses.                   |
| Practice           | Keep reviews due first, followed by skill choices. The page heading need not occupy a permanent second toolbar.                                                                     |
| Library            | Keep search and the filter disclosure available while scrolling; bound expanded filter choices on phones. Library remains reference/search.                                         |
| Profile            | Keep identity and statistics in normal flow with shell navigation available.                                                                                                        |
| Study              | Keep unit context and the single activity-drawer trigger available above the independent content scroller. Reuse the existing activity hierarchy instead of adding another tab bar. |
| Specialist lessons | Keep one section disclosure and progress indicator while scrolling on mobile. Use the existing rail on desktop and avoid sticky controls on very short viewports.                   |
| Scored exercises   | Retain the shared header outside the question scroller, including its narrow-container layout.                                                                                      |

## Performance and maintainability findings

The first production build passed the existing bundle gates. Its static required
JavaScript closures measured 437.9 KiB gzip for startup, 471.2 KiB for Library,
and 625.8 KiB for pronunciation (limits: 490, 520 and 720 KiB respectively).
These are build sizes, not measured Core Web Vitals or mobile network timings.

The largest remaining loading concern is `sentenceMedia`: approximately 22.3 MB
minified / 2.9 MB gzip. `src/app/content/sentenceMedia.ts` statically imports the
reviewed registry and builds a first-match lookup. A future performance change
should load bounded registries on demand and prove identical IDs, URLs and
duplicate precedence for every existing entry. The registry and R2 mappings
remain read-only in this work; the existing unusually large bundle allowance
has not been raised.

The shared UI barrel previously re-exported the sentence-media resolver through
`SentenceQuestionSupport`. That made generic UI imports depend on registry
initialization, particularly in tests where production tree shaking is absent.
Resolver callers now import the content module directly; presentation components
and the shared UI barrel no longer re-export it. An architecture regression test
rejects loading the resolver when importing ordinary controls. This preserves
the resolver implementation and every registry entry.

The usage registry is approximately 1.05 MB minified / 309 KB gzip. Existing
dictionary, story, specialist and scenario splits remain in place. No new runtime
package was introduced for texture or navigation. The changes reuse shared
components, CSS tokens, container queries, and the existing navigation-height
observer rather than adding scroll listeners to individual lesson screens.

The deployment investigation found that the remote/published revision was
`7cfc4b5e`, while the workspace already contained the unpushed `d84c6701` media
commit. Published revision checks, HTML, SPA fallback and all 13 referenced
bundles passed. The preceding CI failure was its dependency audit. Zod,
Happy DOM and Vitest were updated to patched releases; the resulting dependency
audit reported no known vulnerabilities. A pre-existing peer-range mismatch
remains between ESLint 10 and the declared supported range of jsx-a11y.

Happy DOM 21 also exposes native animation cancellation promises that Motion's
event-based animation driver does not consume. Component tests now use Motion's
JavaScript animation fallback by removing native animation capability from the
test environment. Unhandled errors are still reported normally, and real-browser
tests retain native animation support. The six previously affected test files
passed their focused rerun without unhandled errors.

The existing audio audit referenced an undeclared `tsx` executable. It is now
declared as a development dependency, and the read-only audit passes without
changing media files or registries.

## Verification boundaries

The targeted mobile regressions passed for 320 px enlarged English and Arabic
study layouts, drawer dismissal/focus return, and sticky specialist navigation.
Theme contrast and keyboard disclosure component tests also passed before the
full release-gate run. Additional checks cover the darkest possible texture
pixel and scenario caption configuration.

The full verification run and final results are recorded with the release work.
Automated axe checks and token calculations do not establish full WCAG 2.2 AAA
conformance. A criterion-by-criterion audit, representative screen-reader checks,
and real-device usability testing remain necessary for such a claim.
