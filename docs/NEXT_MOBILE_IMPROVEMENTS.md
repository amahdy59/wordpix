# Recommended next mobile improvements

Based on the 5 October 2026 mobile review and the implemented first batch. This is a proposed backlog, not an implementation or a claim that the remaining issues have been resolved.

## Next batch: make the learning journey easier to understand

Prioritize the journey from choosing a lesson to finishing and returning for review. Keep the five global tabs, stable unit IDs, authored content, and all R2 references unchanged.

1. **Home → unit entry:** replace repeated orientation and truncated word lists with one learning outcome, an accurate duration, and one primary action. Preview what the learner will practise before starting.
2. **Study:** show the current unit and activity without clipping; distinguish study navigation from global navigation. Keep the primary instruction, Listen control, answer state, and next action visible at 320px and enlarged text.
3. **Practice / reviews:** implement clear first-use, due, overdue, caught-up, and unavailable states. Do not show an unmeasured value as zero. Make the next review time understandable.
4. **Completion / recovery:** explain what was learned and saved, then provide one next action. Verify retry, interrupted session, microphone denial, timer pause, and failed save behavior before changing progression.
5. **Focused accessibility validation:** test the changed journey with keyboard, Arabic RTL, 200% browser text, VoiceOver, and TalkBack. Measure contrast, target size, and focus visibility for changed states. Automated scans alone do not prove AAA.

This batch should avoid adding new dashboards, metrics, rewards, or course models. Those increase scope without resolving the main journey's ambiguity.

## Sequence after the next batch

1. **Discovery and clarity:** optional courses, Library active filters, specialist-course summaries, Profile metric explanations, and Settings organization.
2. **Level model and content correctness:** A1–C2 preferences/placement plus a separately approved contextual-definition review. These require data and domain checks, not just UI edits.
3. **Polish based on evidence:** guest onboarding, useful course previews, safe-area refinements, and any remaining copy. Retain semantic tokens and reduced-motion support.

For every implementation batch, run typecheck, unit tests, lint, and related mobile E2E. Ship through the repository's release gates and review policy. Preserve existing offline/sync behavior unless a dedicated state-model change is explicitly included.
